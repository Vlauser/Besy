# Treffit

Дейтинг Mini App для Telegram: свайп-колода, взаимные матчи, чаты в реальном
времени, события города и Live-режим — плюс фирменная механика Treffit, где
фото открывается только после реального разговора.

```
treffit/
├── backend/       FastAPI + PostgreSQL: API, WebSocket, миграции, тесты
├── frontend/      Vite + React + Tailwind: Mini App
├── docs/          концепция, схема БД и API
└── docker-compose.yml
```

## Быстрый старт

Нужны Python 3.11+, Node 20+, PostgreSQL 14+.

```bash
# 1. база
createdb treffit

# 2. бэкенд
cd backend
python -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env          # впишите TREFFIT_SECRET_KEY и TREFFIT_BOT_TOKEN
export TREFFIT_ALLOW_DEV_AUTH=true    # вход в браузере без Telegram
.venv/bin/alembic upgrade head
.venv/bin/python -m scripts.seed      # 6 демо-анкет и 3 события
.venv/bin/uvicorn app.main:app --reload

# 3. фронтенд (в другом терминале)
cd frontend && npm install && npm run dev
```

Откроется `http://localhost:5173`. Вне Telegram нет `initData`, поэтому
появится экран Dev Login со списком демо-профилей. Запросы к `/api` vite
проксирует на бэкенд — CORS настраивать не нужно.

Через Docker то же самое одной командой:

```bash
TREFFIT_SECRET_KEY=... TREFFIT_BOT_TOKEN=... docker compose up --build
```

## Два режима продукта

Флаг `TREFFIT_BLIND_MODE` переключает главное продуктовое правило.

| | `true` (по умолчанию) | `false` |
|---|---|---|
| Фото в колоде | скрыто, виден только градиент | видно сразу |
| Когда открывается | после 3 своих сообщений в чате | сразу |
| На что похоже | Treffit из `docs/concept.md` | классический Twinby |

Порог живёт на сервере (`TREFFIT_REVEAL_THRESHOLD`), а не в интерфейсе:
до него API физически не отдаёт ни URL, ни байты файла.

## Что умеет

**Знакомство и анкета** — вход по `initData` без отдельной регистрации,
отдельные согласия по 152-ФЗ, проверка 18+, до 6 фото с модерацией,
мини-тест из 6 карточек, фильтры по полу, возрасту и городу.

**Поиск** — свайпы с перетаскиванием и кнопками (лайк, пропуск,
суперлайк), дневной лимит лайков, «кто вас лайкнул» в Premium. Вкладка
**Карты** — тот же подбор в виде скретч-карт: закрытая карта не содержит
вообще ничего, кроме своего id, анкета приходит только в ответе на
стирание.

**Чаты** — WebSocket: сообщения, «печатает», прочитано, уведомление о
матче. Скретч-открытие фото по достижении порога, у каждой стороны свой
счётчик.

**События и Live** — список событий города, «пойду», чек-ин по координатам
с проверкой радиуса и окна события, список отметившихся рядом.

**Безопасность** — блокировки, жалобы с автобаном по пяти независимым
жалобщикам, мягкое удаление профиля, снятие EXIF с загруженных фото.

**Платежи** — Telegram Stars (`XTR`): Premium, буст, пачка лайков; вебхук
с проверкой секрета и защитой от повторного начисления.

**Модерация фото** — NudeNet локально, без внешних сервисов и без оплаты за
проверку: модель лежит внутри пакета, сеть не нужна. Явное обнажение
отклоняется автоматически, спорное уходит человеку в очередь. Политика
намеренно осторожная: ложный отказ на живой анкете дороже лишней ручной
проверки.

**Верификация анкет** — селфи со случайным жестом, который назначает сервер
и который нельзя перевыбрать. Украденный набор фото не пройдёт: под жест
сегодняшнего дня нужен живой человек. Селфи видит только модератор и оно
удаляется сразу после проверки.

**Push-уведомления** — бот пишет в Telegram тому, кто сейчас не в сети:
новое сообщение, матч, результат модерации и верификации. Внутри чата стоит
кулдаун, чтобы быстрая переписка не превратилась в двадцать пингов.

**Бот** — `/start` с кнопкой запуска Mini App, `/help`, кнопка меню, единый
вебхук на все апдейты Telegram, включая обязательный ответ на
`pre_checkout_query` (без него платёж отменяется).

**Модерация в один тап** — новое фото или селфи бот сразу присылает
модератору в Telegram с кнопками «Одобрить» и «Отклонить», так что заявка
закрывается за минуту, а не висит до следующего захода в админку.

**Админка** — `/admin/*`: очереди фото и верификаций, жалобы, баны,
статистика, ручной запуск синка событий. Доступ по `telegram_id` из
настроек, а не по флагу в БД — скомпрометированный аккаунт не выдаст себе
права модератора.

## Масштабирование

По умолчанию хаб WebSocket внутрипроцессный и сервис работает в один
воркер. Задайте `TREFFIT_REDIS_URL` — события начнут расходиться через
Redis pub/sub, и воркеров можно поднять сколько нужно: пользователь,
подключённый к воркеру 1, получит сообщение, отправленное на воркере 2.
Присутствие («в сети») тоже уезжает в Redis с TTL, чтобы падение процесса
не оставляло людей вечно онлайн.

```bash
TREFFIT_REDIS_URL=redis://localhost:6379/0 \
  .venv/bin/uvicorn app.main:app --workers 4
```

Если Redis недоступен при старте, сервис не падает — он пишет ошибку в лог
и продолжает работать на локальном хабе.

## События из KudaGo

```bash
.venv/bin/python -m scripts.sync_events ekb 3
```

Для регулярного обновления — cron раз в час:

```
0 * * * * cd /srv/treffit/backend && .venv/bin/python -m scripts.sync_events >> var/sync.log 2>&1
```

Разово из админки — `POST /admin/events/sync`.

## Тесты

```bash
cd backend && .venv/bin/python -m pytest        # 118 тестов
```

По умолчанию идут на временном SQLite — никаких сервисов не нужно.
Против настоящего диалекта:

```bash
TREFFIT_DATABASE_URL="postgresql+asyncpg://treffit@localhost/treffit_test" \
  .venv/bin/python -m pytest
```

Тесты кросс-воркерной доставки требуют живой Redis и пропускаются без него:

```bash
TREFFIT_TEST_REDIS_URL=redis://localhost:6379/15 .venv/bin/python -m pytest tests/test_realtime.py
```

Браузерный сквозной прогон (нужны поднятые бэкенд с сидом и `npm run dev`):

```bash
cd frontend && npx playwright install chromium && npm run e2e
```

Он проверяет весь цикл: вход → свайп → взаимный лайк → матч по WebSocket →
чат → живая доставка сообщения → скретч-открытие фото → и что у второй
стороны фото всё ещё закрыто.

## Подключение к Telegram

1. `@BotFather` → `/newbot`, токен в `TREFFIT_BOT_TOKEN`.
2. `/newapp` → URL, где раздаётся `frontend/dist`; полученную ссылку
   `https://t.me/ваш_бот/app` положить в `TREFFIT_MINI_APP_URL`.
3. Зарегистрировать вебхук, команды и кнопку меню одной командой:

```bash
TREFFIT_PUBLIC_URL=https://ваш.домен/api python -m scripts.setup_bot
python -m scripts.setup_bot --status   # проверить, что Telegram достучался
```

4. `TREFFIT_ADMIN_TELEGRAM_IDS` — ваш `telegram_id`, чтобы открылась
   админка на `/docs` (раздел admin).
5. В проде обязательно `TREFFIT_ALLOW_DEV_AUTH=false` — иначе кто угодно
   выпустит себе сессию на любой `telegram_id`.

Установка на сервер — `sudo bash deploy/bootstrap.sh` делает всё до
домена. Полная инструкция — **[`docs/deploy.md`](docs/deploy.md)**:
systemd, nginx с TLS, бэкапы, таймер синка событий и раздел «Проверка в
Telegram» с тем, что нельзя проверить локально.

## Что осталось за рамками

- **Проверка в настоящем Telegram** — путь `initData`, хаптика,
  BackButton, геолокация и Stars написаны по документации и покрыты
  юнит-тестами, но на живом клиенте не выполнялись ни разу. Это самый
  большой невыясненный риск; снимается первым же деплоем по
  `docs/deploy.md`.
- **Мониторинг и rate limiting** — нет ни метрик, ни алертов, ни
  ограничения частоты запросов.
- **Уведомление Роскомнадзора** по 152-ФЗ подаётся до начала обработки
  данных; экран согласий готов, юридическая часть — нет.
- **Веб-интерфейс админки** — очереди работают через API и кнопки в
  Telegram; отдельной веб-страницы со списком нет.
- **Групповые свидания (v2)** из `docs/concept.md`.
- **Тонкая настройка модерации** — пороги подобраны консервативно и их
  стоит откалибровать на живом потоке фото (`POST /admin/photos/{id}/rescan`
  перепроверяет старые фото после смены порогов).
- **Автоматическая сверка селфи с анкетой** — сейчас жест сверяет человек;
  сравнение лиц моделью не делается.

Подробности решений — `docs/concept.md`, схема и эндпоинты —
`docs/schema_api.md`.
