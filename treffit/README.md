# Treffit

Дейтинг Mini App для Telegram. Ядро продукта: фото открывается только после
реального разговора (3 сообщения), обнаружение совпадений — через физические
скретч-карты, а не свайп или список.

## Быстрый старт

```bash
npm install
npm run dev
```

Откроется на `http://localhost:5173`. Основной интерфейс — `src/App.jsx`,
рабочий кликабельный прототип всего флоу (тест → матчи → чат → reveal),
уже на реальном React + Tailwind, без Telegram-специфичного кода.

## Структура

```
src/App.jsx          — прототип интерфейса, весь UI-флоу и state
docs/concept.md       — сводка ВСЕХ решений: механика, IA, дизайн, стек, право
docs/schema_api.md    — схема PostgreSQL + список API-эндпоинтов для бэкенда
docs/treffit_concept_deck.pptx — презентация концепции (для непрограммной аудитории)
```

**Начни с `docs/concept.md`** — там весь контекст решений одним файлом,
не нужно ничего домысливать.

## Что уже сделано (прототип)

- Мини-тест: 6 вопросов, тап-выбор
- Матчи: пачка скретч-карт (настоящий canvas, зернистое стирание,
  проверка по реально стёртой площади, не по длине пути пальца)
- Карточка совпадения: анимированное кольцо %, флаги совпадений, бейдж события
- Чаты: список + блайнд-чат с порогом reveal (свой счётчик на каждого участника)
- Reveal фото: тот же скретч-движок, что и у карточек совпадений
- Профиль, Live-баннер (пока статичный мок)

## Чего нет (следующий шаг)

- Реального бэкенда — все данные сейчас в состоянии компонента (`MATCHES`,
  `chatsState` и т.д.), ничего не сохраняется между сессиями
- `initData`-авторизации Telegram — есть только заглушка идеи в schema_api.md
  (`POST /auth/telegram`)
- Реального гео/Live-режима — `LocationManager` из Telegram WebApp SDK не подключён
- Синхронизации событий с существующим ботом KudaGo

Стек для бэкенда уже решён: FastAPI (Python) на Aeza VPS, PostgreSQL,
Telegram Stars + Точка Банк для платежей. Подробности — в `docs/`.
