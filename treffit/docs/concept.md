# Treffit — концепция (сводка решений)

Дейтинг Mini App для Telegram. Ниша: не свайп-дейтинг, а «сначала разговор, потом фото».

## Название
**Treffit** — от финского *treffit* (свидание, разговорное). Проверено: значение чистое,
без второго смысла. Бонус — в финском есть готовое сложное слово **sokkotreffit**
(«слепое свидание»), которое прямо описывает механику продукта.

Отклонённые варианты: `Bilera` (баскск. на самом деле «встреча», не «свидание»),
`Stefnu` (обрезанный `Stefnumót` — сам по себе значит «политика»/«судебная повестка»).
Урок: не обрезать заимствованные слова без проверки корня.

## Ядро продукта
Фото анкеты скрыто, пока не пройден порог диалога — это не фича поверх свайпа,
а архитектурное решение, вокруг которого строится всё остальное.

## Механизм матчинга (вместо доступа к чатам/группам)
- Доступ к Telegram-группам/каналам пользователя **технически недоступен** через
  Mini App API (в `WebApp` нет метода, который бы это отдавал) и был бы токсичен
  по 152-ФЗ.
- Вместо этого — мини-тест: 6 карточек-сценариев «или-или» (тап, не свайп).
  По мотивам Twinby (там тест проходят один раз при регистрации, % совместимости
  виден в ленте) — у нас короче и встроено в сам жест приложения.
- Ответы становятся темами для блайнд-чата (icebreaker), а не мёртвым грузом.

## Обнаружение — скретч-карты (ключевая, «цепляющая» механика)
Вкладка «Матчи» — не список и не свайп-колода, а **пачка скретч-карт**.
Каждый кандидат скрыт под фольгой; пользователь физически стирает её пальцем/мышью,
чтобы узнать имя, % совместимости и бейдж события.

Технически — canvas с `globalCompositeOperation: destination-out`, зернистое
(не гладкое) стирание мелкими частицами вдоль движения. Открытие карты
происходит по **реальной доле стёртой площади** (семплирование alpha-канала
по сетке), а не по длине пути пальца — иначе можно было быстро поскрести
в одном месте и обмануть механику.

Тот же движок используется для главного момента — **открытия фото в чате**.

## Карточка совпадения (Match Detail)
- Кольцо совместимости — анимированное, растёт от 0% при открытии экрана
  (аналог Twinby, где % — герой-метрика).
- Разбор совпадений — иконки-флаги (буквальная отсылка к терминологии Twinby
  «зелёные флаги»), 2 пункта на карточку.
- Бейдж общего события, если есть.

## Блайнд-чат и reveal
- Фото скрыто до порога — **3 отправленных самим пользователем сообщения**
  (не общее число сообщений в переписке — у каждого участника свой счётчик
  и свой момент reveal).
- По достижении порога — появляется скретч-карта с фото внутри чата.
- После reveal — галочка верификации на аватаре (подтверждённая деталь
  из настоящего Twinby: «ищи галочку» на проверенных анкетах).

## События и Live-режим (не MVP, но спроектировано)
- Источник данных — уже существующий бот событий Екатеринбурга на KudaGo.
- Событие — не отдельный экран для свайпа, а бейдж на карточке + буст в ленте.
- **Live-режим**: 2 часа вокруг начала события открывается временная лента —
  только те, кто чекинился на месте (`LocationManager.getLocation()`).
  Создаёт срочность вместо бесконечного скролла.

## Групповые свидания (v2)
После удачного reveal — не сразу тет-а-тет, а низкорисковая встреча компанией,
привязанная к тому же событию. Отличие от Twinby (у них «пара на пару»):
у нас это следующий шаг после доверия, а не отдельный режим с начала.

## Информационная архитектура
5 вкладок: **Дом · Тест · Матчи · Чаты · Профиль**.
Карточка совпадения и чат — «выезжающие» экраны поверх табов (без нижней
панели), не отдельные табы.

- **Дом** — статус Live, статус теста, счётчик неоткрытых карт (без спойлера
  содержимого — только количество).
- **Тест** — 6 вопросов, тап по одной из двух карточек-ответов.
- **Матчи** — пачка скретч-карт.
- **Чаты** — список начатых разговоров с превью последнего сообщения.
- **Профиль** — свои ответы теста, без фото.

## Дизайн (финальное направление)
Прошли несколько итераций (тёплый органичный → тёмный техно → тёплое золото
под Золотое Яблоко → текущее). Итог — синяя палитра по образцу Twinby:
- Основной синий (`#3D6BFF`-ish) — везде, где действие/акцент.
- Глубокий индиго (`#2A3B8F`-ish) — только для «драгоценных» моментов:
  рамка вокруг открытого фото, кольцо совместимости, скретч-фольга.
- Один шрифт (Plus Jakarta Sans) везде — без «сказочного» серифа.
- Без прыгающих/плавающих анимаций, без блёсток-конфетти — читалось как
  детское игровое приложение, убрано полностью.
- Скругления умеренные, не «капли»/органика.

## Стек (утверждён)
- **Frontend**: Telegram WebApp API + React (см. `src/App.jsx` — рабочий
  кликабельный прототип всего флоу).
- **Backend**: FastAPI (Python), на существующем Aeza VPS, отдельный
  systemd-сервис.
- **БД**: PostgreSQL. Схема — `docs/schema_api.md`.
- **Авторизация**: `initData` от Telegram, без отдельной регистрации.
- **Платежи**: Telegram Stars (`XTR`) для цифровых фич внутри Mini App
  (обязательное требование площадок) + эквайринг Точка Банк для остального,
  если понадобится.
- **Хранилище**: `CloudStorage` Telegram (до 1024 ключей/юзера) годится
  для лёгкого состояния без похода на бэкенд.

## Юридические моменты (152-ФЗ)
- Фото, гео и ответы теста — данные повышенной чувствительности, нужно
  отдельное явное согласие (не общая политика конфиденциальности).
- Обязательная проверка 18+.
- Модерация фото (NSFW) перед публикацией.
- Верификация анкет с первого дня — для дейтинга фейки фатальнее, чем
  для обычного сервиса.

## Критично для бэкенда (не только UI)
Реveal — это проверка на сервере, не блюр на клиенте. Смотри
`docs/schema_api.md`, раздел «Критичный момент безопасности»:
эндпоинт с фото обязан отказывать в 403, если `revealed_*` не `true`
в БД — иначе фото достаётся из devtools раньше времени.
