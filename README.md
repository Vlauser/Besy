# AXIOMANTIC — сайт с админкой

Дизайн и тексты — из исходников дизайнера (Next.js), перенесённые
на PHP-шаблоны. Контент правится через админку, файлы React больше не нужны.

## Обновление с прошлой версии

Структура контента изменилась полностью, поэтому `data/content.json`
заменяется. Учётные записи и накопленные заявки при этом сохраняются.

Порядок: залить архив в `/tmp`, затем одной строкой

```
cd /tmp && rm -rf axm && unzip -q axiomantic-export-cms.zip -d axm \
 && cp -a /var/www/axiomantic/data/users.json /tmp/users.bak 2>/dev/null \
 && cp -a /var/www/axiomantic/data/leads.json /tmp/leads.bak 2>/dev/null \
 && cp -a axm/axiomantic-cms/. /var/www/axiomantic/ \
 && cp -a /tmp/users.bak /var/www/axiomantic/data/users.json 2>/dev/null \
 && cp -a /tmp/leads.bak /var/www/axiomantic/data/leads.json 2>/dev/null \
 && chown -R www-data:www-data /var/www/axiomantic \
 && chmod -R 775 /var/www/axiomantic/data /var/www/axiomantic/uploads \
 && rm -rf axm /tmp/users.bak /tmp/leads.bak && echo ОБНОВЛЕНО
```

Перед обновлением сделайте копию:
`tar czf ~/backups/before-redesign.tgz -C /var/www/axiomantic .`

# AXIOMANTIC — сайт с админкой

Сайт на PHP без базы данных и без composer. Весь контент лежит в `data/content.json`,
редактируется через админку. Заявки падают в Telegram и на почту.

---

## Что нужно от сервера

- PHP **8.1 или новее** (`php -v`)
- Расширения: `json`, `mbstring` (обычно уже стоят)
- Apache с `mod_rewrite` **или** nginx + PHP-FPM
- База данных **не нужна**

---

## Установка за 6 шагов

**1. Загрузите файлы**

Всё содержимое архива — в корень сайта, например `/var/www/axiomantic`.

**2. Дайте права на запись двум папкам**

```bash
cd /var/www/axiomantic
sudo chown -R www-data:www-data data uploads
sudo chmod -R 775 data uploads
```

Без этого админка не сможет сохранять правки. На shared-хостинге через панель
поставьте на `data` и `uploads` права `775`.

**3. Настройте веб-сервер**

*Apache* — ничего делать не нужно, `.htaccess` уже в архиве. Убедитесь, что
в конфиге сайта стоит `AllowOverride All`.

*nginx* — возьмите `nginx.conf.example`, поправьте `root` и версию PHP-FPM
в строке `fastcgi_pass`, затем:

```bash
sudo cp nginx.conf.example /etc/nginx/sites-available/axiomantic.ru
sudo ln -s /etc/nginx/sites-available/axiomantic.ru /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

**4. Подключите домен и HTTPS**

A-запись `axiomantic.ru` → IP сервера. Затем сертификат:

```bash
sudo certbot --nginx -d axiomantic.ru -d www.axiomantic.ru
```

**5. Создайте администратора**

Откройте `https://axiomantic.ru/install.php`. Страница сама проверит сервер
и покажет, что не так. Придумайте логин и пароль от 10 символов.

**6. Удалите установщик**

```bash
rm /var/www/axiomantic/install.php
```

Повторно он всё равно не сработает, но пусть не лежит.

Готово — админка на `https://axiomantic.ru/admin/`.

## Что редактируется из админки

**Главная:** первый экран · полоса с цифрами · аксиомы · процесс по часам ·
теорема · календарь запуска · кейсы · отзывы · вопросы и ответы · финальный блок

**Другие страницы:** портфолио · услуги · тарифы и цены · контакты · политика

**Страница «Сколько стоит»** — `/landing-price`. Отдельная посадочная под
запросы о цене: из чего складывается сумма, пакеты с комплектациями,
что оплачивается отдельно, сроки, вопросы о цене. У каждого пакета можно
указать ключ проекта — под ним появится ссылка на кейс.

Цены попадают в микроразметку: Яндекс может показать сумму прямо
в сниппете. Если в цене есть слово «от», в разметку идёт минимальная
цена, а не точная — иначе это обещание, которого вы не давали.

**Отзывы** — раздел «Отзывы», показываются на главной и на странице цены.
Пока не добавлено ни одного — блока на сайте нет. Оценка от 1 до 5
попадает в разметку, и Яндекс может показать звёзды в выдаче; средняя
считается только по отзывам с проставленной оценкой.

Не добавляйте выдуманные отзывы. Это прямой запрет в вашем SEO-ТЗ
и реальный риск фильтра за накрутку поведенческих и репутационных
сигналов — отменить его сложнее, чем получить.

**Страницы проектов.** У каждой работы из портфолио есть своя страница
по адресу `/projects/<ключ>`: описание, задачи, что сделали, технологии,
переходы на соседние проекты. Собирается из полей карточки в разделе
«Портфолио» — отдельно ничего верстать не нужно.

Ключ проекта задаёт адрес страницы. Очистили ключ — страницы не будет,
карточка в портфолио поведёт сразу на сайт клиента. У каждой работы есть
свои `title` и `description` для выдачи и галочка «закрыть от индексации».

**Настройки:** контакты и шапка · SEO страниц · SEO общие · политика и cookie · тексты в формах ·
уведомления и аналитика

Блоки со списками (кейсы, отзывы, вопросы, тарифы) можно добавлять, удалять
и менять местами. Картинки грузятся прямо в форме, складываются в `uploads/`.

### Главное правило: пусто — значит скрыто

Очистили поле в админке — то, что оно выводило, пропадает с сайта.
Ничего не остаётся «висеть»: ни пустого заголовка, ни рамки с отступами.

- очистили подпись поля формы — **исчезает всё поле**. Так убирают
  лишние вопросы: чем короче форма, тем больше заявок;
- очистили заголовок, кнопку или картинку — пропадает только они;
- очистили в блоке **всё** — блок не выводится совсем;
- оставили подпись только у одной кнопки способа связи — переключателя
  не будет, форма сразу покажет нужное поле.

У таких полей в админке стоит жёлтая пометка «пусто — скроется»:
наведите на неё, и будет написано, что именно исчезнет.

Убрать нельзя два поля: контакт и галочку согласия на обработку данных.
Без первого некуда отвечать, без второго заявку нельзя принять по 152-ФЗ —
сервер её просто не примет.

### Предпросмотр

Кнопка «Предпросмотр» в шапке раздела открывает живую страницу сайта
прямо в редакторе, прокрученную к нужному блоку. Есть переключатель
«Компьютер / Телефон» и кнопка «Обновить» — после сохранения видно,
что правка доехала.

В предпросмотре не показывается баннер cookie и не запускается Метрика:
ваши правки не попадают в статистику, а баннер не закрывает тот самый
блок, который вы пришли посмотреть.

### Как найти нужную настройку

Разделов больше двадцати, держать в голове, что где лежит, незачем.
В боковом меню есть поиск — ищет по названию раздела, по месту на сайте
и по подписям всех полей внутри. Открывается по `Ctrl+K` или клавише `/`.
Например, «цвет» приведёт в «Дизайн», «телефон» — в «Контакты и шапку».

У каждого раздела в шапке написано, где он находится на сайте, а рядом
кнопка «Посмотреть» — открывает нужный блок в соседней вкладке.

## Заявки

Приходят в раздел «Заявки» и дублируются:

- **в Telegram** — создайте бота у [@BotFather](https://t.me/BotFather), вставьте
  токен и chat_id в «Уведомления и аналитика». Свой chat_id узнаете у
  [@userinfobot](https://t.me/userinfobot);
- **на почту** — укажите адрес там же. Работает через функцию `mail()`;
  если письма не доходят, подключите SMTP на уровне сервера.

Заявки выгружаются в CSV. Встроена защита: honeypot-поле и лимит 5 заявок
с одного IP в час.

### Откуда пришёл клиент

Вместе с заявкой сохраняются метки рекламы: `utm_*`, `yclid` из Директа,
`gclid`, `roistat`. Запоминается **первый** заход — именно он привёл человека
на сайт, даже если заявку он оставил через неделю и с закладки.

Видно в трёх местах: в карточке заявки, в уведомлении Telegram
и отдельными колонками в выгрузке CSV. По ним считается, какое объявление
окупается, а какое просто жжёт бюджет.

Метки хранятся, только если человек принял cookie. Отказался — возьмётся
то, что осталось в адресе на момент отправки.

## Аналитика

ID Яндекс.Метрики — в «Уведомления и аналитика». Счётчик запускается
только после согласия на cookie. Включены вебвизор, карта кликов
и точный показатель отказов.

### Цели

Все цели — тип «JavaScript-событие». Заведите их в Метрике с этими
идентификаторами:

| Идентификатор | Когда срабатывает |
|---|---|
| `lead` | заявка отправлена и принята сервером |
| `form_open` | открыто окно заявки |
| `form_start` | человек начал заполнять форму |
| `click_telegram` | клик по ссылке на Telegram |
| `click_email` | клик по почте |
| `click_phone` | клик по телефону |
| `project_click` | клик по кейсу в портфолио |
| `faq_open` | раскрыт вопрос в блоке «вопросы и ответы» |
| `scroll_25` … `scroll_100` | глубина прокрутки страницы |

Зачем столько: Директ умеет оптимизировать показы под цель, но одной
заявки ему мало — она набирается неделями, и алгоритму не на чем учиться.
Промежуточные цели набираются за дни. Ставьте `form_start` или
`click_telegram` как вспомогательную цель в кампании, пока заявок мало.

Разница между `form_open`, `form_start` и `lead` показывает, где теряются
люди: открыли и ушли — не убеждает предложение, начали и бросили —
мешает сама форма.

## SEO

Два раздела в настройках.

**«SEO — страницы»** (доступно редактору) — для каждой из четырёх страниц:

- `title` и `description`
- своя картинка для соцсетей
- галочка «закрыть от индексации»

**«SEO — общие»** (только админ):

- основной адрес сайта — идёт в `canonical` и карту сайта
- приставка к title и запасной title
- картинка для соцсетей по умолчанию (1200×630) и фавикон
- **закрыть весь сайт от индексации** — на время разработки
- содержимое `robots.txt`
- коды подтверждения для Яндекс.Вебмастера и Google Search Console
- данные организации для микроразметки

Генерируется автоматически:

- `https://axiomantic.ru/sitemap.xml` — только из открытых страниц, с картинками работ
- `https://axiomantic.ru/robots.txt` — со ссылкой на карту сайта и `Clean-param`
- `<script type="application/ld+json">` — граф микроразметки, см. ниже
- Open Graph и Twitter Card — превью ссылки в Telegram, WhatsApp и ВК
- хлебные крошки на внутренних страницах

Файлов `sitemap.xml` и `robots.txt` на диске нет, они отдаются на лету —
менять их надо через админку, а не по FTP.

После запуска добавьте сайт в Яндекс.Вебмастер и Search Console: вставьте код
подтверждения в «SEO — общие», сохраните, затем нажмите «Проверить» в панели
поисковика и отправьте туда адрес карты сайта.

### Адреса пишутся без слэша на конце

Решение зафиксировано: `/landing-price`, а не `/landing-price/`. В SEO-ТЗ
адреса записаны со слэшем — это расхождение сознательное, роутер приводит
оба варианта к одному виду. Менять правило после того, как страницы
попадут в индекс, будет уже дорого: каждый переезд адреса стоит позиций.

### Один адрес у одной страницы

Роутер сам уводит `301`-м на канонический адрес: со слэшем на конце,
в верхнем регистре, с `/index.php`, с задвоенными слэшами. Без этого
Вебмастер видит несколько разных документов с одинаковым содержимым
и делит между ними вес.

Галочка «Уводить на основной адрес» в «SEO — общие» добавляет к этому
переброс с `www` и с `http`. Выключите её, если сайт должен открываться
ещё и по тестовому домену. На `localhost` и по IP она не срабатывает
в любом случае.

### Clean-param — важно для Директа

Директ дописывает к адресу `yclid`, кампании — `utm`. Для Яндекса
`/?yclid=123` и `/` — две разные страницы. Тысяча кликов по объявлению
даёт тысячу дублей главной, и она проседает в выдаче.

Директива `Clean-param` в `robots.txt` говорит роботу склеивать такие
адреса. Она уже собирается автоматически со списком меток Директа,
Google Ads и коллтрекинга. Если вставите свой текст `robots.txt`
в админке — не забудьте перенести её туда же.

### Микроразметка

Отдаётся графом связанных сущностей, а не одной карточкой:

- `Organization` — название, юр. данные из подвала, город, способы связи, соцсети
- `WebSite` и `WebPage` — сайт и текущая страница
- `BreadcrumbList` — хлебные крошки, Яндекс показывает их вместо адреса
- `FAQPage` — вопросы и ответы, разворачиваются прямо в выдаче
- `ItemList` услуг с ценами и `ItemList` работ

Всё берётся из контента: отредактировали услугу в админке — поменялось
и в разметке. Проверить можно в Вебмастере, раздел «Инструменты →
Валидатор микроразметки».

## 152-ФЗ: политика, согласие, cookie

**Страница политики** — `https://axiomantic.ru/privacy`. Текст лежит в админке,
раздел «Политика и cookie», правится обычным текстом с разметкой
(`## заголовок`, `- пункт`, `**жирный**`). HTML вставить нельзя, он экранируется.
Ссылка на страницу стоит в подвале, у чекбокса в формах и в cookie-баннере.

**Согласие в формах.** Галочка обязательна: без неё заявка не отправится
не только в браузере, но и на сервере — бот не обойдёт. Вместе с заявкой
сохраняется доказательство согласия: точный текст, который человек видел,
дата, IP и редакция политики. Видно в карточке заявки и в выгрузке CSV.

Текст меняется в «Тексты в формах», поле «Текст согласия». Кусок
в `[[двойных скобках]]` превращается в ссылку на политику.

**Cookie-баннер** показывается один раз, выбор запоминается на год
(localStorage + cookie). Кнопки «Принять» и «Отклонить» — тексты меняются
в админке.

Важно: **Яндекс.Метрика загружается только после согласия**. Нажали
«Отклонить» — счётчик не подключится вообще, а не просто скроет баннер.
Поэтому не вставляйте код Метрики вручную в «Произвольный код в head»,
иначе он выполнится до согласия и смысл баннера потеряется.

Дату редакции в разделе «Политика и cookie» обновляйте при каждой правке
текста — она попадает в заявки как отметка о том, с какой версией
согласился человек.

## Что нужно сделать вне сайта

Сайт закрывает техническую часть. Эти обязанности лежат на вас как на ИП
и на сайте не решаются.

**1. Подать уведомление в Роскомнадзор — до начала обработки.**
Обязанность по ст. 22 152-ФЗ, распространяется на всех операторов,
включая ИП с одной формой на сайте. Подаётся через `pd.rkn.gov.ru`
или Госуслуги. С 30 мая 2025 года (420-ФЗ) штраф за неподачу вырос
до 300 000 ₽, повторно — до 500 000 ₽. Проверить себя можно в реестре
операторов на том же сайте.

**2. Оформить внутренние документы (ст. 18.1).**
Политика на сайте — только часть. Дополнительно нужны приказ о назначении
ответственного за обработку ПДн и перечень принимаемых мер защиты.
Роскомнадзор запрашивает их первыми.

**3. Держать данные на сервере в РФ (ч. 5 ст. 18).**
Сбор и хранение данных россиян — только в базах на территории России.
Проверьте, где физически стоит ваш сервер, и что резервные копии
не уезжают в зарубежное облако.

**4. Не подключать зарубежные сервисы без уведомления (ст. 12).**
Внешние шрифты, CDN, зарубежные счётчики и виджеты чата передают IP
посетителя за границу — это трансграничная передача, о ней уведомляют
РКН отдельно. Поэтому шрифты в этой сборке локальные, а из аналитики —
только Яндекс.Метрика. Прежде чем добавлять любой сторонний скрипт,
проверьте, куда он шлёт запросы.

**5. Знать порядок действий при утечке (ч. 3.1 ст. 21).**
Первичное уведомление в РКН — в течение 24 часов с момента обнаружения,
отчёт о результатах внутреннего расследования — в течение 72 часов.
Порядок утверждён приказом РКН от 14.11.2022 № 187.

**6. Реклама — только по отдельному согласию (ч. 1 ст. 18 38-ФЗ).**
Галочка про рассылку в форме отдельная и не предустановленная.
Писать с предложениями можно только тем, кто её отметил. Хранить
подтверждение — обязанность отправителя, оно сохраняется в заявке.

**7. Чек через «Мой налог» — кассы не нужно (НПД).**
Плательщики НПД освобождены от применения ККТ по п. 2.2 ст. 2 54-ФЗ.
Чек формируется в приложении «Мой налог» и направляется клиенту —
на почту, в мессенджер или ссылкой. Зарегистрировать онлайн-кассу
на НПД в принципе нельзя: этого режима нет в списке при регистрации ККТ.
Счёт на оплату тоже выставляется прямо в «Мой налог».

Держите в поле зрения три ограничения режима: годовой доход до 2,4 млн ₽,
запрет на наёмных работников по трудовым договорам (подрядчики по ГПХ
и другие самозанятые — можно), запрет на перепродажу чужих товаров
и услуг. При выходе за лимит статус НПД теряется, и тогда касса
становится обязательной.

**8. Сведения об ИП на сайте (ст. 9 ЗоЗПП).**
Наименование, ОГРНИП и ИНН выводятся в подвале, меняются в разделе
«Контакты и шапка». Потребитель должен получить их до сделки.

Это ориентир, а не юридическое заключение. Перед запуском покажите
документы юристу, который ведёт ИП.

## Раздел «Дизайн»

Настройки → «Дизайн». Меняет оформление всего сайта, не трогая код:

- шесть цветов: тёмный фон и текст, светлый фон, фон карточек, акцент
  для кнопок и ссылок, линии на светлом и на тёмном;
- ширина содержимого на больших экранах;
- размер основного текста и межбуквенное расстояние в заголовках;
- скорость бегущей строки — отдельно для компьютера и телефона.

Пустое поле означает «оставить как в стилях». Текущее значение написано
в подсказке под каждым полем, так что вернуть исходный вид можно,
просто очистив поле.

Значения проверяются: цвет обязан быть шестизначным HEX, числа — попадать
в допустимый диапазон. Всё остальное молча игнорируется, поэтому опечаткой
сайт не сломать и чужой код через эти поля не вставить.

Чего раздел не меняет: сетку, порядок секций, скругления и сами шрифты —
это по-прежнему `assets/style.css`.

## Картинки и скорость

Скорость загрузки Яндекс учитывает и в выдаче, и при оценке посадочной
страницы в Директе. Поэтому:

- каждая картинка лежит ещё и в WebP — весит в 5–10 раз меньше при том же
  виде. Браузер сам выбирает формат, старым отдаётся оригинал;
- у картинок проставлены `width` и `height`, чтобы текст под ними
  не прыгал при загрузке;
- иллюстрация первого экрана грузится в первую очередь, остальные —
  по мере прокрутки;
- шрифты кириллицы предзагружаются, статика кэшируется на год.

Картинки из админки получают WebP-двойника сами. Если положили файлы
по FTP — пережмите одной командой:

```bash
cd /var/www/axiomantic && php tools/make-webp.php
```

Оригиналы остаются на месте, повторный запуск пропускает уже готовое.
Нужен PHP с расширением `gd` и поддержкой WebP — проверить:

```bash
php -r 'var_dump(gd_info()["WebP Support"]);'
```

## Что менять в коде, а не в админке

Дизайн живёт в `assets/style.css`, разметка — в `tpl/*.php`.
Через админку меняются тексты, цифры, картинки и порядок блоков,
но не сетка, отступы и типографика.

Если дизайнер захочет поменять именно оформление — правки вносятся
в CSS, тут админка не поможет. Это нормальное разделение: контент
отдельно, дизайн отдельно.

## Если что-то не работает

**Белый экран** — включите показ ошибок: в `inc/config.php` временно добавьте
`ini_set('display_errors','1'); error_reporting(E_ALL);`, посмотрите текст,
потом уберите обратно.

**Админка не сохраняет** — права на `data` (шаг 2).

**Открывается только главная, остальные страницы 404** — не работает
переадресация: для Apache включите `mod_rewrite` и `AllowOverride All`,
для nginx проверьте строку `try_files`.

**Картинки не грузятся** — права на `uploads` и `upload_max_filesize`
в php.ini не меньше 8 МБ.

**Ошибка 500 сразу после загрузки файлов (Apache)** — почти всегда дело
в `.htaccess`. По очереди закомментируйте: строку `Options -Indexes`
в `uploads/.htaccess` (требует `AllowOverride Options` или `All`),
затем блок `RedirectMatch`. После каждой правки проверяйте сайт.
Точная причина будет в логе ошибок Apache.

**Ошибка 500 на nginx** — смотрите `nginx -t` и путь к сокету PHP-FPM
в строке `fastcgi_pass`: версия PHP должна совпадать с установленной
(`ls /run/php/`).

**Первый запуск.** Перед тем как открывать сайт, включите показ ошибок:
в `inc/config.php` добавьте `ini_set('display_errors','1');
error_reporting(E_ALL);`. Пройдите по всем страницам, зайдите в админку,
сохраните раздел, загрузите картинку, отправьте тестовую заявку.
Убедились, что ошибок нет — уберите эти строки обратно.
